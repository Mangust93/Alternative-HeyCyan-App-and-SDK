# CODEX Build Review: JDK 21 / Room

Date: 2026-05-24

## Scope

This review is limited to the build/toolchain blocker for the NativeAutomation MVP.
No glasses SDK flow, BLE/P2P/media-transfer code, `DeviceBindActivity`,
`PictureVm`, `AlbumDownloader`, or `NativeAutomationEngine` was changed.

## What Was Broken

`litertlm-android-0.10.0-api.jar` contains Java class version `65.0`
(Java 21). A Gradle build executing annotation processing on Java 17 cannot
read those LiteRT API types and fails in `:app:kaptDebugKotlin` with
`class file has wrong version 65.0, should be 61.0`.

Although the shell launches Java 21, this checkout had a user-level setting
outside the repository:

```properties
/root/.gradle/gradle.properties:
org.gradle.java.home=/usr/lib/jvm/java-17-openjdk-amd64
```

Before the fix, `./gradlew --version` therefore showed:

```text
Launcher JVM: 21.0.10
Daemon JVM:   /usr/lib/jvm/java-17-openjdk-amd64 (from org.gradle.java.home)
```

On that Java 17 daemon, Room's KAPT processor also terminated with:

```text
androidx.room.compiler.processing.javac.JavacBasicAnnotationProcessor
NullPointerException: access$getProcessingEnv... must not be null
```

When Gradle was explicitly executed on the installed JDK 21 before editing,
`:app:kaptDebugKotlin --rerun-tasks` completed successfully. Therefore the
checked-out project does not require a Room upgrade or KAPT-to-KSP migration
to address this blocker; the actionable problem is selecting the required
daemon JVM consistently.

## Minimal Fix Applied

Added `gradle/gradle-daemon-jvm.properties`:

```properties
# This file is generated by updateDaemonJvm.
toolchainVersion=21
```

Gradle 8.13 daemon JVM criteria are intended to be checked into version
control and take precedence over `JAVA_HOME` and `org.gradle.java.home`.
After adding the file, ordinary `./gradlew --version --no-daemon` reports:

```text
Daemon JVM: Compatible with Java 21, any vendor (from gradle/gradle-daemon-jvm.properties)
```

Room remains on `kapt`; no KSP plugin, dependency, Room version, LiteRT
dependency, or product source was changed.

Reference:
<https://docs.gradle.org/current/userguide/gradle_daemon.html#sec:daemon_jvm_criteria>

## Remaining Compilation Blockers

With Gradle now on Java 21, both requested builds proceed beyond Room/KAPT and
expose unrelated Kotlin source errors already present relative to
`ai/codex-fix-native-automation-mvp`:

- Missing `AutoPairManager` references from `MainActivity.kt`,
  `BluetoothReceiver.kt`, `DeviceBindActivity.kt`, and `MyApplication.kt`.
- Missing Moonshine API symbols (`JNI`, `Transcriber`,
  `TranscriptEvent`, and `TranscriptEventListener`) in the transcription
  integration sources.

These are outside this build/toolchain-only change and include a file
explicitly excluded from modification (`DeviceBindActivity`), so they were
not altered here.

## APK Result

No verified debug APK was produced. `assembleDebug` is now blocked at
`:app:compileDebugKotlin`, after the JDK/Room/KAPT stage has passed.
